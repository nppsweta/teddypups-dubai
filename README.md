First inspect and use the live reference URL directly if it is reachable from your environment. Review the homepage, navigation, footer, all linked internal pages, typography, colors, spacing, imagery, mobile layout, and visible interactions. Reproduce the actual pages and content structure as closely as possible. Do not invent unsupported factual claims, prices, phone numbers, addresses, testimonials, or puppy availability. If the reference cannot be accessed, state that limitation in the project and build a polished, coherent approximation using only verifiable brand/subject context, with clearly editable placeholder content rather than pretending it is exact.

Implement a polished puppy boutique / teacup puppy website for TeddyPups U.A.E. with responsive desktop/tablet/mobile behavior, accessible semantic markup, working mobile navigation, working internal navigation, reusable components, and functioning visible UI (filters/search if present, FAQ accordion, inquiry/contact form validation and success state, CTA links, gallery interactions as appropriate). Use local or remotely hosted high-quality puppy imagery that fits the visual reference; avoid broken images. Ensure no nonfunctional dead buttons.

Use a maintainable React + TypeScript + Tailwind component structure. Add page-level routing for all pages discovered on the reference; if unable to discover them, create sensible routes matching the actual navigation only when evidenced, and avoid overbuilding. Include metadata and responsive details. Add a README explaining project structure, setup, key components, functionality, and known deviations from reference. Keep a concise record of important implementation decisions and limitations so they can be included in the assignment walkthrough.

Before finishing, test all routes and interactive controls, inspect responsive breakpoints, fix console/runtime errors, and summarize what was verified versus what could not be verified. Do not claim pixel-perfect parity unless actually checked against the reference.
